## 1. 문서 목적

본 문서는 교사 대시보드(`/teacher`)에 신규 메뉴 **「모둠 활동」**(모둠 자리·역할 부여)을 추가하기 위한 요구사항을 정의한다. 초등 과학 수업의 **협력 학습·모둠 운영·역할 순환**을 디지털로 지원하고, 교사의 반복 업무(명단 정리, 모둠 편성, 역할 배정, 주간 교체)를 자동화하는 것을 목표로 한다.

---

## 2. 배경 및 문제 정의

### 2.1 교육적 배경

개념기반 탐구 수업에서는 3~4명 **소집단(모둠)** 이 실험·토의·기록·발표를 분담한다. Project Zero 및 협력학습 연구에서 **역할 부여(Role assignment)** 는 참여 균형, 책임감, 메타인지를 높이는 핵심 전략이다.

### 2.2 현장 문제

| 문제 | 설명 |
|------|------|
| P1 | 명단·성적 분포·성별·분리 조건을 종이·엑셀로 매번 수동 편성 |
| P2 | 「같은 모둠 피하기」 조건(떠듬·다툼 등) 누락으로 갈등 재발 |
| P3 | 월별 모둠 재편성 시 **과거 동료 이력** 추적 어려움 |
| P4 | 역할(이끄미·나누미 등) **주간 교체** 일정 관리 번거로움 |
| P5 | 역할 수행 칭찬이 구두에 그치고, 학생이 자신의 모둠·역할을 확인하기 어려움 |

### 2.3 문제 정의

> **교사가 반별 학생 명단·성적 분포를 디지털로 관리하고, 성별·상·중·하·분리 조건을 반영한 6모둠 편성·주·보조 역할 부여·월별 재배치·주간 역할 순환·모둠 활동 칭찬을 「모둠 활동」 탭에서 수행하며, 학생은 자신의 모둠·역할 현황을 조회할 수 있어야 한다.**

## 3. 목표 및 설계 원칙

### 3.1 핵심 목표

| ID | 목표 | 성공 기준(예시) |
|----|------|-----------------|
| GR1 | 반별 명단 디지털화 | CSV 업로드 후 자동 저장, 개별 수정·삭제 |
| GR2 | **성적 분포** 별도 관리 | 상(1)·중(2)·하(3) 코드로 기록, 편성 알고리즘 입력 |
| GR3 | 공정한 모둠 자동 편성 | 6모둠×3~4명, 남녀 1~2명, 상·중·하 혼합 |
| GR4 | 분리 조건 준수 | 교사 정의 유형별 「같은 모둠 금지」 100% 반영 |
| GR5 | 월별 재편성 | 3~12월, 동일 모둠 이력·동료 3회 초과 동반 방지 |
| GR6 | 역할 순환 | 주·보조 역할 배정 + **1주 주기** 자동 교체(1주차 6/29 월) |
| GR7 | 학생 조회 | 학생 화면에서 **현재 모둠·역할 현황** 표시 |
| GR8 | 모둠 활동 칭찬 | **「모둠 활동」 탭 전용** 주간 칭찬(기존 `/teacher/badges`와 분리) |

### 3.2 설계 원칙

1. **교사 통제 우선**: 자동 편성은 기본값이며, 교사가 수동 조정·재구성 가능.
2. **설명 가능성**: 「왜 이 모둠인가」 조건 위반 여부를 UI에 표시.
3. **점진적 확장**: 역할 명칭·분리 유형명은 **교사가 커스터마이즈** 가능(초기 4역할 + 기본 분리 유형 제공).
4. **기존 플랫폼 연계**: 학생 프로필(학년·반·번호·이름)과 Firestore 교사 권한 체계 재사용.
5. **프라이버시**: 성적 분포·성별은 **해당 반 교사만** 편집; 학생 화면에는 **모둠·역할·칭찬**만 노출.
6. **칭찬 체계 분리**: 학습지·탐구용 **칭찬 배지**(`/teacher/badges`)와 **모둠 활동 칭찬**은 별도 운영.

| **학생** | `/my` 또는 홈 **모둠·역할** 섹션 | 현재 모둠 번호, 주역할·보조역할, 이번 주 기간 조회 |

- **모둠 활동** 탭에서 역할을 잘한 학생에게 주간 칭찬을 부여한다(학습지 배지와 별도).

**페르소나 — 민수 (5학년 2반 학생)**  
- 홈 또는 `/my`에서 **3모둠 · 주역할: 지키미 · 보조역할: 나누미 · 6/29~7/5** 를 확인한다.

## 6. 상세 기능 요구사항

### 6.1 F-GR01 역할 정의 (기본값)

| 코드 | 역할 ID | 명칭 | 책임(기본 설명) |
|------|---------|------|-----------------|
| **1** | `leader` | **이끄미** | 사회자, 발표 |
| **2** | `supplier` | **나누미** | 실험 준비물 준비, 배부 |
| **3** | `recorder` | **지키미(기록이)** | 시간, 안전, 기록 |
| **4** | `organizer` | **깔끄미** | 모둠 테이블 정리, 태블릿 정리 |

**요구사항**

- GR01-1: 반(클래스) 단위로 역할 세트 저장(코드 1~4 고정, **명칭만** 추후 편집 가능).
- GR01-2: 역할 추가·이름 변경 — Phase 2.

#### 6.1.1 모둠 인원별 역할 배정 규칙

| 모둠 인원 | 역할 배정 | 비고 |
|-----------|-----------|------|
| **4명** | 역할 1~4 **각 1명** (1:1) | 주역할만 존재(= 해당 역할 전담) |
| **3명** | 역할 **2개** — **1개 역할은 2명**에게 중복 부여 | 1명=주역할+보조역할, 1명=주역할, 1명=주역할 |

**3명 모둠 상세 규칙**

- 4역할 중 **3개 역할**이 모둠에 배치되고, **1개 역할은 해당 주에 모둠에 없음**(주차별 로테이션).
- 중복된 역할을 가진 2명 중: **주역할(primary)** 과 **보조역할(secondary)** 로 구분.
- **수업·기록·UI 안내는 주역할 위주**로 활동하도록 표시.
- 보조역할 학생은 같은 역할 카테고리의 **보조·지원** 담당(예: 나누미 주 + 나누미 보조).

**예시 (3명, Week1)**  
| 학생 | 주역할 | 보조역할 |
|------|--------|----------|
| A | 이끄미(1) | — |
| B | 지키미(3) | — |
| C | 나누미(2) | 깔끄미(4) ← 보조만 |

또는 알고리즘이 **한 역할을 두 학생에게** 부여할 때 한 명은 주·한 명은 보조.

### 6.7 F-GR06 역할 부여 및 주간 교체

#### 6.7.1 주차·기준일

| 항목 | 값 |
|------|-----|
| **1주차 시작일** | **2026년 6월 29일(월)** |
| 주 시작 요일 | **월요일** (고정) |
| 교체 주기 | **1주** — 매주 월요일 0시(또는 수업 시작 시점) 역할 스케줄 갱신 |
| UI 표시 | 「N주차: M/D(월) ~ M/D(일)」 |

**주차 계산**

```text
weekIndex = floor((today - anchorDate) / 7일) + 1
anchorDate = 2026-06-29 (Monday)
```

교사가 학년도별 **anchorDate**를 설정할 수 있게 — v1 기본값 2026-06-29.

#### 6.7.2 기능 요구

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| GR06-1 | 편성 확정 후 「역할 랜덤 배정」 | Must |
| GR06-2 | **4명 모둠**: 역할 1~4 각 1명 | Must |
| GR06-3 | **3명 모둠**: 3역할 배치 + 1역할 중복 → **주역할·보조역할** | Must |
| GR06-4 | **매주 월요일** 자동 로테이션(1주 단위) | Must |
| GR06-5 | UI: **현재 주차·기간** (예: 1주차 6/29~7/5) | Must |
| GR06-6 | 학생·교사 화면 모두 **주역할 강조**, 보조역할 보조 표시 | Must |
| GR06-7 | 교사 수동 역할 스왑 | Should |

```typescript
interface StudentRoleAssignment {
  studentId: string;
  groupNo: number;
  weekIndex: number;
  weekStart: string;       // ISO date, Monday
  weekEnd: string;         // Sunday
  primaryRoleCode: 1 | 2 | 3 | 4;
  secondaryRoleCode?: 1 | 2 | 3 | 4 | null;  // 3명 모둠만
}
```

## 10. 수용 기준 — MVP

1. 교사가 **성적 분포** 탭에서 학생별 상(1)/중(2)/하(3)을 저장한다(100점 필드 없음).
2. 3명 모둠에서 2명에게 **같은 역할 코드**가 부여될 때 **주역할·보조역할**이 구분된다.
3. **1주차 6/29(월)~7/5(일)** 이 UI에 표시되고, 다음 주 역할이 자동 갱신된다.
4. 학생이 로그인하면 **모둠 번호·주역할·(보조역할)·기간**을 본다.
5. **모둠 활동 칭찬**은 `/teacher/groups`에서만 부여되며 `/teacher/badges`와 섞이지 않는다.
6. 분리 조건·6모둠·성별·상중하 혼합 편성이 v0.1 수용 기준을 만족한다.
